## Теоретическое обоснование

### 2.1. Структура класса DbContext и его назначение

Класс DbContext является центральным звеном между классами модели и базой данных. Он выполняет следующие функции:

- **Управление соединением:** открывает и закрывает соединения с БД по мере необходимости
- **Маппинг:** сопоставляет свойства классов C# со столбцами таблиц базы данных
- **Отслеживание изменений:** следит за состоянием объектов, загруженных из базы

Основные составляющие ApplicationContext (наследника DbContext):

1. **DbSet<TEntity>:** свойства типа DbSet представляют таблицы в базе данных
2. **OnConfiguring:** метод конфигурации строки подключения и провайдера БД
3. **OnModelCreating:** метод настройки схемы модели через Fluent API

### 2.2. Жизненный цикл сущностей и отслеживание изменений

Когда сущность извлекается из БД через контекст, EF Core начинает её отслеживать. Состояние сущности может быть:

- **Unchanged** - без изменений
- **Added** - новая сущность
- **Modified** - изменённая сущность
- **Deleted** - удалённая сущность

Каждое состояние определяет, какие SQL-команды будут сгенерированы при вызове SaveChanges(). Ключевой особенностью является то, что для сохранения изменений достаточно вызвать метод SaveChanges() — Change Tracker анализирует все отслеживаемые объекты и генерирует соответствующие SQL-команды (INSERT, UPDATE, DELETE).

### 2.3. Реализация CRUD-операций в EF Core

- **Create:** добавление объекта в DbSet через `context.Contacts.Add(contact)`. Состояние меняется на Added
- **Read:** выполнение LINQ-запросов к DbSet: `context.Contacts.ToList()` или `Where(...)`
- **Update:** изменение свойств отслеживаемого объекта. Специальные методы не требуются
- **Delete:** удаление объекта через `context.Contacts.Remove(contact)`. Состояние меняется на Deleted

### 2.4. Разделение моделей и сущностей

В приложении используются два класса Contact:

- **Entities.Contact** — сущность БД, соответствует таблице в базе данных
- **Models.Contact** — модель представления с валидацией, используется в интерфейсе

## Описание выполненных действий

### 4.1. Анализ сгенерированного класса DbContext

Открыт файл `PhoneBookDbVlasova2307g1Context.cs`, сгенерированный при реверс-инжиниринге базы данных. Изучено свойство `DbSet<Contact>` и метод `OnModelCreating`, содержащий конфигурации отношений, индексов и ограничений. Установлено, что имя сущности `Contact` совпадает с именем класса модели, однако находится в пространстве имён `PhoneBook.Entities`. Поскольку в проекте также существует `PhoneBook.Models.Contact`, требуется явное указание пространства имён для устранения неоднозначности.

### 4.2. Внедрение DbContext во ViewModels через DI

В класс `ContactsListViewModel` добавлено приватное поле `_context` типа `PhoneBookDbVlasova2307g1Context`. Конструктор расширен параметром context — DI-контейнер автоматически передаёт экземпляр контекста. Аналогично модифицирован конструктор `ContactEditViewModel`.

### 4.3. Реализация операции чтения (Read)

В конструкторе `ContactsListViewModel` выполняется загрузка контактов из базы данных с маппингом Entities.Contact → Models.Contact:

```
var contactsFromDb = _context.Contacts
    .Select(c => new Models.Contact(c.Name, c.Phone))
    .ToList();
Contacts = new ObservableCollection<Models.Contact>(contactsFromDb);
```

### 4.4. Реализация операции создания (Create)

Метод `AddContact` в `ContactsListViewModel` дополнен логикой сохранения в БД:

1. Проверка дубликата по номеру телефона в коллекции
2. Создание `Models.Contact` с валидацией
3. Создание `Entities.Contact` и добавление в контекст: `_context.Contacts.Add(entityContact)`
4. Сохранение изменений: `_context.SaveChanges()`
5. Добавление модели в коллекцию `Contacts` только после успешного сохранения
6. Очистка полей ввода и вывод информационного сообщения

Операции 3-6 обёрнуты в try-catch для обработки исключений БД.

### 4.5. Реализация операции редактирования (Update)

В `ContactEditViewModel` реализован метод `SaveContact`:

1. Поиск сущности в БД по старому номеру телефона: `_context.Contacts.FirstOrDefault(c => c.Phone == _originalContact.Phone)`
2. Обновление полей найденной Entity: `entityToUpdate.Name = EditName`, `entityToUpdate.Phone = EditPhone`
3. Сохранение изменений: `_context.SaveChanges()`
4. Вывод сообщения об успехе и навигация обратно к списку контактов

Обработка ошибок через try-catch.

### 4.6. Реализация операции удаления (Delete)

Метод `DeleteContact` в `ContactsListViewModel` реализует:

1. Запрос подтверждения через `_dialogService.ShowYesOrNo`
2. Поиск Entity в БД по номеру телефона выбранного контакта
3. Удаление из контекста: `_context.Contacts.Remove(entityToDelete)`
4. Сохранение изменений: `_context.SaveChanges()`
5. Удаление из коллекции `Contacts.Remove(SelectedContact)` только после успешного сохранения

Обработка ошибок через try-catch.

### 4.7. Обновление интерфейса

Интерфейс обновляется автоматически благодаря использованию `ObservableCollection<Models.Contact>`:
- При добавлении: `Contacts.Add(contact)` — UI отображает новый контакт
- При удалении: `Contacts.Remove(SelectedContact)` — UI удаляет строку
- При редактировании: после навигации обратно список загружается заново в конструкторе `ContactsListViewModel`
